# @zorsh/effect

## 0.1.0

### Minor Changes

- ec3938f: First public release. `Borsh.toCodec(schema)` derives a Borsh codec from the encoded side of a native Effect 4 schema, keeping its checks, brands, transformations and service requirements. It supports integers `U8` through `U128` and `I8` through `I128`, exact `F32` and `F64`, booleans, UTF-8 strings, `Bytes` and `fixedBytes(n)`; structs, tuples, `Unit`, vectors and `fixedArray(item, n)` for Rust `[T; N]`; Rust enums from `Schema.TaggedUnion`, unions of tagged structs, string `Schema.Literals` and `Schema.Enum`, with declaration-index discriminants or explicit ones via `Borsh.discriminants`; `Schema.Option` and `Schema.Result`; and `ReadonlyMap`, `ReadonlySet`, `HashMap` and `HashSet` in Rust key order. Each operation has a `maxBytes` limit (16 MiB by default), and binary failures are native Schema issues with a path and byte offset.
- 77b7515: Bound work on untrusted input with limits you set explicitly. A new `maxItems` option caps the total number of vector, fixed-array, map and set items per operation, nested ones included, charged as soon as each length is known. It has no default limit and applies to encoding too. `Borsh.maxLength(n)` bounds one length prefix, whatever it counts: vector items, the UTF-8 bytes of a string, the bytes of `Borsh.Bytes`, map entries or set members. It is an ordinary Effect check, so `Schema.is`, `make` and Arbitrary samples agree with it, and the binary layer also enforces it right after reading a length and before writing one, failing with `Length N exceeds maxLength (M)`, the path and the byte offset, even under `disableChecks`. Put it on the encoded side, before any transformation; on a layout without a length prefix, `toCodec` throws. Effect's own length and size checks, such as `Schema.isMaxLength`, are never read as wire limits; they run in the schema pass like any other check. The README gains an "Untrusted input" section.
- 6790ffe: Add `Borsh.decodePrefixEffect` and `Borsh.decodePrefixSync`, which decode one value at an offset in a larger buffer and return a `Borsh.Prefix`, `{ value, offset }`, where `offset` is where the next value starts. They share the codec's compiled layout, limits, schema pass and errors, but allow bytes after the value. `maxBytes` caps the bytes the value uses rather than the buffer, and a read whose length or count shows the value cannot fit fails with "Value exceeds maxBytes" however short the buffer is. Error offsets are positions in the buffer, and an offset outside the buffer is a defect. Decoding middleware can recover from schema-pass failures but not from binary ones, which leave no offset to return. Schemas that always encode to zero bytes, such as `Borsh.Unit`, are rejected when the decoder is built, so a decoding loop always advances. The README gains a "Decoding from a larger buffer" section.
- 541e03f: Add `Borsh.withBytes(schema)`, which decodes to `{ value, bytes }`, where `bytes` is a copy of the exact bytes the value was read from, for signatures, hashes and forwarding as received. It adds nothing to the wire format. Encoding writes `value` and fails at `["bytes"]` if that doesn't reproduce `bytes`, so stale bytes are never sent; build new outgoing values with the plain schema. Arbitrary samples carry matching bytes, JSON codecs see a struct with base64 `bytes`, and equivalence compares both. The README gains a "Keeping the exact bytes" section.

### Patch Changes

- dea9791: Make Effect's `Arbitrary.schema` produce encodable samples. `F32` samples exact binary32 integers within ±2^24. `fixedBytes(n)` and `fixedArray(item, n)` use a native exact-length check, so samples have exactly `n` bytes or items. `fixedArray(item, n)` builds `Schema.Array(item)`, so JSON Schema output gains `minItems` and `maxItems`, and annotations, brands and transformations apply to the result as to any array schema. Other lengths now fail Schema validation, including `Schema.is` and `make`, with "Expected a value with a length of n". The README documents fixture generation, including strings with lone surrogates and zero-sized vectors.
